# Ma chere Victoria

Статический многостраничный сайт художницы с русской и английской версиями.

## Сборка

Нужен Node.js 22+. Для сервера установите зависимости через `pnpm install --frozen-lockfile` (lock-файл включён в проект):

```bash
npm run build
```

Скрипт читает словари `src/locales/ru.json` и `src/locales/en.json`, проверяет совпадение ключей и создаёт корневой маршрутизатор, 404 и страницы для каждого языка:

- `index.html` — маршрутизатор с сохранением `search/hash`;
- `ru/index.html`, `en/index.html` — главные;
- `about/`, `series/`, `shop/`, `order/`, `contacts/`, `portfolio/` — подстраницы каждого языка.

Сгенерированные HTML-файлы не редактируются вручную. Сборка использует общую оболочку `src/site.template.html`, шаблоны разделов `src/pages/` и словари. Она проверяет паритет ключей и наличие всех значений, используемых шаблонами. Корневой маршрутизатор и локализованная 404 формируются в `scripts/build.mjs`.

Без npm сборку можно запустить командой `node scripts/build.mjs`. Оформление находится в `css/site.css`. Публикация выполняется отдельно через существующий GitLab pipeline.

Главная содержит навигацию Bonjour. Ссылка «Принты» открывает `shop/?filter=print`; поддерживаются также `filter=all` и `filter=original`. Выбор фильтра сохраняется в URL и восстанавливается при Back/Forward и смене языка.

Браузерная проверка Dev 2: `node scripts/verify-dev2.cjs` (нужен отдельно установленный Playwright с Chromium). Можно указать `PLAYWRIGHT_MODULE` и `CHROMIUM_PATH` для уже установленного браузерного окружения; `SCREENSHOT_DIR` включает сохранение снимков.

Artist Statement (`about/`) использует временные тексты RU/EN и AI-иллюстрацию мастерской до получения утверждённых текста и фотографии. Изображение и его статус задаются конфигурацией сборки. Браузерная проверка: `node scripts/verify-dev3.cjs` с теми же переменными окружения, что для Dev 2.

Старые якоря `#manifesto`, `#shop`, `#contacts` ведут на соответствующие страницы, `#about` — к Bonjour на главной. Корзина хранится под прежним ключом `mcv-cart` и доступна на всех страницах. Портрет пока использует существующий файл со встроенными надписью и росчерками; для чистого фото нужен исходник.

На локальном сервере проверяйте сайт из корня репозитория, например:

```bash
python3 -m http.server 8080
```

Откройте `http://localhost:8080/`. Переключатель языка сохраняет английский выбор в `localStorage` под ключом `mcv-locale`; при отсутствии сохранённого выбора используется русский.

## Dev 4: каталог и заявки

`catalog/works.json` — единый источник работ и метаданных изображений. `shared/catalog.mjs` читает его и рассчитывает ревизию. Сборка автоматически создаёт `js/gallery.js`; его не редактируют вручную. Порядок, ID, цены и изображения прежнего каталога сохранены. Для Dev 5 заменяется адаптер `loadCatalog()`, а магазин и сервер продолжают получать `{items, images, revision}`.

Корзина хранит только ID под прежним ключом `mcv-cart`. «Оформить заявку» открывает локализованную страницу `order/`: имя и email обязательны, телефон и комментарий необязательны. Контактные данные не записываются в localStorage. Заявка не является оплатой или резервом.

`POST /api/orders` принимает `{locale, items:[{id}], catalogRevision, requestId, customer:{name,email,phone,comment}, website:''}`. Сервер определяет стоимость и валюту по каталогу, проверяет наличие, отправляет письмо только на `victtoress@gmail.com` и возвращает `201 {orderId}` после принятия SMTP-сервером. При `409` клиент показывает актуальные работы/цены и просит повторить подтверждение. Ошибка отправки оставляет анкету и корзину на экране.

Для одного `requestId` сервер предотвращает повторную отправку в пределах одного процесса в течение 10 минут. После перезапуска этот кеш теряется. Проверяются Origin, размер запроса, поля и лимит 5 запросов за 10 минут с IP. SMTP-пароли и адрес отправителя находятся только в окружении сервера. Для локального запуска: `node --env-file=.env server/index.mjs`; заполните `.env` по `.env.example`. Статический сервер сам по себе почту не отправляет — `/api/orders` должен проксироваться на Node-сервис.

## Развёртывание API (отдельный этап)

1. Создайте служебного пользователя `mcv-orders` и каталог `/opt/mcv-orders` вне публичного web root. Скопируйте туда `server/`, `shared/`, `catalog/works.json`, `package.json` и `pnpm-lock.yaml`; установите Node.js 22+ и зависимости (`pnpm install --prod --frozen-lockfile`).
2. Сохраните SMTP-настройки и точный `SITE_ORIGIN` без завершающего `/` в `/etc/mcv-orders.env` с владельцем root и правами 600. Отправитель `SMTP_FROM` должен быть разрешён вашим почтовым провайдером. Для порта 465 задайте `SMTP_SECURE=true`, для 587 — false (STARTTLS).
3. Установите `deploy/mcv-orders.service` в systemd, проверьте путь `/usr/bin/node`, затем запустите сервис. Он слушает только `127.0.0.1:3100`. Используйте один процесс, чтобы кеш повторных запросов и лимиты были общими.
4. Включите `deploy/nginx-orders.conf` в существующий HTTPS server block. Nginx перезаписывает `X-Forwarded-For`, поэтому здесь допустим `TRUST_PROXY=true`; без этого прокси используйте false. Проверьте конфигурацию nginx перед перезагрузкой.
5. При изменениях каталога синхронно обновляйте JSON в `/opt/mcv-orders/catalog/` и публикуйте результат сборки сайта. API читает файл на каждый заказ. Рассогласование безопасно вызывает пересмотр заказа, а не отправку устаревшей цены.

GitLab rsync публикует только статическую часть: добавлены исключения для серверного кода, зависимостей и `.env*`. Секреты никогда не помещаются в `/var/www/mysite`. Эти изменения не выполняют публикацию и не настраивают реальный SMTP автоматически.

## Проверки

- `node --test tests/server-orders.mjs` — API, валидация, изменения цены/наличия, повторные запросы, сбои и локальный SMTP-приёмник. Реальные письма не отправляются.
- `node scripts/verify-dev4.cjs` — браузерная проверка RU/EN, трёх ширин, анкеты, ошибок, пересмотра цены и успеха (Playwright и переменные окружения аналогичны Dev 2).

## Dev 6: портфолио

`src/data/portfolio.json` содержит проекты отдельно от каталога магазина. Сейчас это три явно помеченных демопроекта — фильм, спектакль и книга. Они не являются реальными работами Виктории. Для настоящих проектов замените записи и установите `isDemo: false`; предупреждение о демоматериалах исчезнет, когда демонстрационных записей не останется. Изображения необязательны: без них используется типографская обложка.

На компьютере наведение открывает предпросмотр книги, нажатие фиксирует её. Повторное нажатие, Escape, кнопка закрытия или нажатие вне полки закрывает книгу. Пока книга зафиксирована, наведение на соседние корешки её не переключает. На сенсорных экранах работает нажатие; Enter/Space работают с клавиатуры. При reduced motion анимация отключена. Без JavaScript проекты отображаются обычным списком.

`node scripts/verify-dev6.cjs` проверяет RU/EN, адаптивность, hover/touch/клавиатуру, возврат фокуса, reduced motion, fallback без JavaScript и сохранение корзины. Для запуска используются те же переменные Playwright, что для Dev 2–4. Dev 5 и новые серверные API для портфолио не нужны.
